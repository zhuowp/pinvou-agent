# Metadata final observation

This T27 component makes the protected metadata publisher's final observation
follow complete history and original-byte verification. It does not enable an
online check, grant current eligibility, clear cleanup barriers or complete T27.

The publisher first finishes all member/prior callbacks, signed graph and water
checks, staged-copy validation, final-original rereads and staging deletion.
It then prepares MetadataFinalization from its actual LiveTimeReadSet in the
same held product guard and native transaction. Preparation authenticates the
complete source and original bootstrap custody and prepares the numeric Root
window before any final counter call.

The opaque view retains exact registration Head/history, time Head/history and
Policy, protected original Root and product Root Head pins. Its bounded checks
use actual retained native keys and ACLs and authenticate the real SCM service.
The dedicated metadata sampler performs these checks before and after actual
Win32 counters. Native incarnation continuity, conservative advancement from the
original signed observation, interval nonregression, Root validity and the
protected lower floor constrain the result. Root decoding and complete history
replay do not occur after that final counter observation before commit.

FinalMetadataObservation borrows this exact view and holds a genuine native
same-source observation. Initial or generic historical samples and serialized
counter DATA cannot substitute for it. The journal writer requires this type;
serialization preserves the existing historical-sample schema. The original
Evidence.received observation remains unchanged.

The existing minimum-expiry predicate additionally requires the final latest
bound to precede every expiring graph body and Root. Equality refuses. The same
transaction retains the sampled floor, writes journal/publication successors,
checks intended records and role Policy, and rechecks the bounded view before
commit. Its own metadata, journal and floor writes are expected changes; time,
registration and Root pins remain fixed. No current-use or physical-COMMIT UTC
guarantee follows from retaining the observation.

Commit uncertainty and any postcommit flush/readback failure remain
StateCommitUnknown. Complete persisted replay occurs after commit, before a
successful historical receipt. The full generic source and historical sampling
interfaces retain their existing checks for other consumers.

The Windows native transaction environment fails its first direct HKCU TxR call
with ERROR_RM_NOT_ACTIVE (6801). Real SCM-backed sampling, privileged native
publication, interrupted commit/restart and simultaneous native scratch/index
transactions remain unverified. Pure DATA checks and compilation cannot replace
those executions. Tests must not construct a fake service or positive native
sample. No E2E or deployment was run.
